Project debrief · Externship

AI Document Intelligence Pipeline

A Python pipeline that turns PDFs, both scanned and digital, into structured, traceable, searchable data.

RoleExtern
WhenAug – Oct 2026
CompanyPfizer
FocusOCR · RAG

The challenge

Important information often lives inside PDFs, and those PDFs come in different forms. Some are scanned images, others are digital text. The goal was to pull key information out of both reliably, in a way reviewers could verify against the original document.

How it works

01IngestHandles 2 PDF formats: scanned and digital
02ReadOCR for scanned pages, text parsing for digital
03ExtractKey fields saved as JSON with page coordinates
04Classify & routeDocuments sorted and sent to the right place
05SearchRAG workflow with metadata filters

What I did

  • Built a Python pipeline that processes 2 PDF formats, choosing OCR or direct text parsing depending on the document type.
  • Extracted key fields into structured JSON with page coordinates, so reviewers can jump straight to where each value came from in the source PDF.
  • Implemented 2 document-handling functions: classification and routing.
  • Built a search workflow using retrieval-augmented generation (RAG) with metadata filters.

Why it matters

Saving page coordinates with every extracted value makes the output traceable. A reviewer doesn't have to trust the AI blindly; they can check every result against the original page.

Tech stack

PythonOCRText parsingJSONRAGMetadata filtering

Project debrief · Externship

Securing an IoT Sensor Pipeline

Finding the weak points in a simulated IoT sensor network, locking down its data pipeline, and testing whether it holds up to attacks.

RoleExtern
WhenNov 2026 – Jan 2027
ProgramIoT Cyber Defense
StatusIn progress

The challenge

Connected sensors constantly send data across a network, and every hop is a chance for someone to read, fake, or replay that data. The goal was to identify those risks in a simulated sensor network and then defend against them.

Approach

01MapTraced data flows through the sensor network
02Model threatsUsed STRIDE to identify security risks
03SecureAdded TLS and device certificates to MQTT
04Stress-testBenchmarked and tested certificate failures
05DetectSimulated and detected replay attacks

What I did

  • Mapped data flows in a simulated IoT sensor network and applied STRIDE threat modeling to identify security risks.
  • Secured a mock MQTT sensor pipeline using TLS and device certificates.
  • Benchmarked 2 configurations, with and without encryption, to compare their behavior.
  • Tested 2 certificate failure scenarios: expired certificates and forged certificates.
  • Simulated replay attacks and tuned 2 detection methods, one based on time windows and one on message counters.

Tech stack

MQTTTLSDevice certificatesSTRIDEThreat modelingAttack simulation
